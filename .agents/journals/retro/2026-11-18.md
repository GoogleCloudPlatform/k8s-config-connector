### Grouped Substantive Human Feedback & Review Findings (108 items across 117 PRs)

#### Pattern 1: Dependency Churn & Unwanted `replace` Directives in `go.mod` / `mockgcp/go.mod`
- **PRs**: #15832, #15415, #15095, #15648, #15461
- **Feedback**:
  - #15832 (gemmahou): *"The version changes in go.mod seem unrelated to ObservabilityTraceScope resource. Please revert if that's unnecessary... There're version bumps for cloud.google.com/go/dataproc/v2, cloud.google.com/go/securitycenter..."*
  - #15415 (gemmahou): *"Only add cloud.google.com/go/observability v0.1.1 and revert other changes that are not related to ObservabilityTraceScope resource in go.mod"*
  - #15095 (gemmahou): *"Seems like only version bump cloud.google.com/go/memorystore v1.9.0 is relevant to the goal of this PR. Why do we have other changes in go.mod?"*
  - #15648 (GinnyJI): *"Revert mockgcp/go.mod (git checkout origin/master -- mockgcp/go.mod) to remove the unrelated cloud.google.com/go/ces v1.0.0 addition."*
  - #15461 (anfernee): *"The replace statement in go.mod is concerning. see if we can remove it."*
- **Root Cause**: Running `go get ...@latest` or `go mod tidy` in the root workspace or `mockgcp/` causes Go to update indirect and transitive dependencies across the entire workspace. Agents committed these collateral diffs and occasionally introduced `replace` directives.
- **Classification**: Coding skill lacked strict post-dependency cleanup instructions and guardrails.

#### Pattern 2: Standalone Unit Tests (`*_test.go`) in `mockgcp/` and `pkg/controller/direct/`
- **PRs**: #15832, #15261, #15476
- **Feedback**:
  - #15832 (gemmahou): *"Remove unit test for mockGCE server"* (`mockgcp/mockobservability/tracescope_test.go`)
  - #15261 (gemmahou): *"Remove unit test for mockGCP code. It's unnecessary."* (`mockgcp/mockaiplatform/hyperparametertuningjob_test.go`)
  - #15476 (anhdle-sso): *"Remove pkg/controller/direct/dialogflowcx/dialogflowcxagent_fuzzer_test.go. Per KCC fuzzer guidelines... we do not create dedicated *_fuzzer_test.go or unit test files inside pkg/controller/direct/<service>/."*
- **Root Cause**: Agents instinctively wrote Go unit tests for newly implemented mock packages and direct controllers. In KCC, MockGCP is tested end-to-end against recorded real GCP logs via `hack/compare-mock` and `tests-e2e-fixtures-suite`, and fuzzers run centrally in `pkg/fuzztesting/fuzztests/...`. Standalone test files in these packages violate repo conventions.
- **Classification**: Coding skills lacked negative constraints ("Do NOT create standalone unit tests").

#### Pattern 3: Redundant `spec.resourceID` Specified in Test Fixtures
- **PRs**: #15897, #15832
- **Feedback**:
  - #15897 (gemmahou): *"There is no need to specify resourceID in the fixtures test, especially since the value is the same as metadata.name. Overseer recently began adding spec.resourceID to maximal tests sometimes. This is harmless, but we don't usually specify this field in fixtures tests to my experience. Because it's KCC-specific field, it doesn't add value when testing the direct controller and mapping logic against real GCP."*
  - #15832 (gemmahou): *"remove resourceID field in fixtures test."*
- **Root Cause**: Coding agents populated `spec.resourceID: ${uniqueId}` in maximal fixtures even when it was identical to `metadata.name`. In KCC, `spec.resourceID` is an acquisition/import escape hatch and should not be populated in standard lifecycle fixtures.
- **Classification**: Coding skills and core testing guidance lacked explicit convention on `spec.resourceID`.

#### Pattern 4: Incomplete Test Fixtures — Omitting `update.yaml` and `dependencies.yaml`

#### Pattern 7: Handling Recursive Types in KRM Schemas
- **PRs**: #15410, #15432

#### Pattern 8: Enforcing Required Fields on Generated Child Structs (`*WithRequired`)
- **PRs**: #15740, #15646
- **Feedback**:
  - #15740 (barney-s): *"Change BigtableClusterSpec.ClusterConfig in apis/bigtable/v1alpha1/bigtablecluster_types.go from *Cluster_ClusterConfig to *Cluster_ClusterConfigWithRequired. Run ./apis/bigtable/generate.sh to emit the WithRequired structs, enforce required autoscaling fields, and update the four required-not-enforced entries in apis/bigtable/judgement_queue.yaml to edited."*
  - #15646 (barney-s): *"Lets add a DeploymentSourceWithRequired and use it for .spec.terraformBlueprint.externalValues.KEY.deploymentSource.deploymentRef... lets wire DeploymentSourceWithRequired into ConfigPreviewSpec"*

- **Classification**: Skill documentation lacked explicit explanation of this deterministic generation mechanism.

2. **Factory Issue Generation for Data Plane Resources and Deprecated Services**:
   - Issue #15504 triggered greenfield types for `VectorSearchDataObject` (PR #15515), which maintainers closed as an out-of-scope data plane resource.
   - Issue #15065 triggered direct controller work for `ContentWarehouseDocumentSchema` (PR #15088), an upstream deprecated service.
   - *Recommendation*: Add pre-flight filtering in issue triage to exclude data plane APIs and deprecated GCP services.

3. **`generate-crds` Timeout in Single-Service Sandboxes**:
   - In PR #15884, running `./apis/cloudbuild/generate.sh` timed out because `dev/tasks/generate-crds` processes all CRDs in the repository.
   - *Recommendation*: Support scoped CRD generation (`dev/tasks/generate-crds --service <service>`) or default `SKIP_GENERATE_CRDS=1` when iterating on mapper/controller logic.

4. **Merge Queue CI Flakiness**:
   - In PR #15446, an approved and ready PR was evicted from the merge queue due to a timeout in `unit-tests-3-of-4`.
   - *Recommendation*: Investigate concurrency limits or shard distribution for long-running unit test suites.
