## 4. Environment, Tooling, and Factory Recommendations

1. **`controllerbuilder generate-mapper` Reference Name Matching**:
   - *Problem*: In PR #15884, when reference field names were made idiomatic (e.g., `RepositoryProjectId` -> `RepositoryProjectRef`), `controllerbuilder generate-mapper` emitted `// MISSING:` and dropped the mapping silently without a compile error or prominent warning.
   - *Recommendation*: Enhance `controllerbuilder generate-mapper` to support fuzzy matching for reference fields by stripping `Ref` and matching normalized proto field names, or emit a clear compile-time warning when a reference field has no corresponding mapping.

2. **Automated Cleanup During Factory Graph Transition**:
   - *Problem*: In PRs #16071 and #16077, single-resource scaffolding PRs had to be manually closed by maintainers because the orchestration pipeline moved to graph-driven triage (`factory-graph`).
   - *Recommendation*: Add automated cancellation or deduplication in the factory coordinator when a resource is queued under a graph runner to prevent redundant single-sandbox PR generation.

3. **Pre-flight Triage Against `BLOCKED_KINDS`**:
   - *Problem*: In PR #15887, an agent attempted to re-implement `VertexAITrainingPipeline`, which was already implemented and on `BLOCKED_KINDS` waiting for release verification under tracking issue #15390.
   - *Recommendation*: Ensure issue triage checks whether a Kind is already present in `dev/tasks/build-release-bundle` (`BLOCKED_KINDS`) before dispatching a greenfield generation workflow.
