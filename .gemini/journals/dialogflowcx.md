# DialogflowCX Journal

## DialogflowCXAgent Direct Controller Implementation

- **Service-Generated Resource ID**: `DialogflowCXAgent` uses server-assigned IDs (UUIDs). Reconciler logic follows the service-generated ID pattern:
  - `Find()` pre-checks if identity is specified (`!a.id.HasIdentitySpecified()`) and returns `false, nil` without calling API when empty.
  - `Create()` does not pass `resource.Name` in request body, letting GCP assign the UUID.
  - On create success, `parsedID.FromExternal(created.GetName())` sets the server-assigned UUID in `a.id.Agent`.
  - `status.externalRef` and `status.name` are populated in status update.
- **Regional Endpoint Construction**: Dialogflow CX API uses endpoint format `{location}-dialogflow.googleapis.com` (e.g. `global-dialogflow.googleapis.com`). Endpoints must be formatted without `:443` port suffix to cleanly align with GAPIC REST client HTTP request URLs.
- **Reconciliation & CompareGreenfieldSpec**: Using `common.CompareGreenfieldSpec` with `DialogflowCXAgentSpec_FromProto` and `DialogflowCXAgentSpec_ToProto` accurately identifies spec field diffs and produces field mask for `UpdateAgentRequest`.

## DialogflowCXGenerator Types & Identity

- **Child Resource Hierarchy**: `DialogflowCXGenerator` is a child resource under `DialogflowCXAgent` (`projects/{project}/locations/{location}/agents/{agent}/generators/{generator}`). Per Greenfield Case B parent standards, it models `spec.parentRef` pointing to `DialogflowCXAgentRef` and omits `ProjectRef` and `Location`.
- **Server-Generated ID**: `CreateGeneratorRequest` does not accept a client-assigned ID parameter (`name` is populated automatically by Dialogflow on creation), so `DialogflowCXGeneratorIdentity` implements `identity.ServerGeneratedIdentity` and `spec.resourceID` is optional and used for acquisition only.
- **ObservedState**: The `Generator` proto message defines no `OUTPUT_ONLY` fields other than `name` (which maps to identity/externalRef); hence `ObservedState` is commented out in status.

## DialogflowCXTool Prepopulation Notes

- **Proto Source Overlay**: `google/cloud/dialogflow/cx/v3/tool.proto` is mirrored into `mockgcp/apis/google/cloud/dialogflow/cx/v3/` along with `data_store_connection.proto` and `dialogflow_v3.yaml` and compiled into `.build/googleapis.pb` via `dev/tools/controllerbuilder/generate-proto.sh`.
- **Mapper Generation**: Removed `ServiceDirectoryConfig` from `--skip-proto` in `apis/dialogflowcx/generate.sh` so `Tool_ServiceDirectoryConfig` mappers are generated automatically for `DialogflowCXTool` without impacting `Webhook_ServiceDirectoryConfig`.
- **Empty Message in Oneof / Spec Validation**: `FallbackPrompt` in `google.cloud.dialogflow.cx.v3.Tool.DataStoreTool` is an empty message (`message FallbackPrompt {}`), requiring an entry in `knownInvalidCRDs` in `tests/apichecks/crds_test.go`.

## DialogflowCXTool Types & Judgement Notes

- **Parent Reference**: Tool resources are children of `DialogflowCXAgent` (`projects/{project}/locations/{location}/agents/{agent}/tools/{tool}`). Modeled as a single required, immutable `spec.parentRef` pointing to `*DialogflowCXAgentRef`. `ProjectRef` and `Location` were removed from spec.
- **Server-Generated ID**: `DialogflowCXTool` IDs are server-assigned UUIDs generated by GCP upon creation. `ResourceID` is optional and immutable, used for acquisition only.
- **Resource References**:
  - `dataStoreRef`: `DataStoreConnection.dataStore` converted to `DataStoreRef *discoveryenginev1alpha1.DiscoveryEngineDataStoreRef`.
  - SecretManager references: `secretVersionForAPIKeyRef`, `secretVersionForTokenRef`, and `secretVersionForClientSecretRef` in authentication configs converted to `*refsv1beta1.SecretManagerSecretVersionRef`.
  - ServiceAccount reference: `serviceAccountRef` in `ServiceAccountAuthConfig` converted to `*refsv1beta1.IAMServiceAccountRef`.
  - ServiceDirectory reference: `serviceRef` in `ServiceDirectoryConfig` converted to `*servicedirectoryv1beta1.ServiceDirectoryServiceRef`.
- **Non-Reference Auth Fields**: `clientID` is an OAuth provider client ID string, and `clientSecret` is a plaintext OAuth secret; both marked as `not-applicable` in `judgement_queue.yaml`.
