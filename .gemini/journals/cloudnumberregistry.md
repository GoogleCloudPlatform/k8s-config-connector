### [2026-09-18] CustomRange Type Scaffolding
- **Context**: Implementing Greenfield direct types for `CloudNumberRegistryCustomRange` resource mapping to GCP `CustomRange` proto.
- **Problem**: 
  1. The fields `ipv4_cidr_range` and `ipv6_cidr_range` in proto map to KRM types. Because KCC mandates standard acronym capitalization rules, the Go field names must use `IPV4CIDRRange` and `IPV6CIDRRange`. If written differently, the autogenerated mapper fails to identify the corresponding proto properties.
  2. The `realm` and `parent_range` properties refer to resources that need proper KCC references. Since `Realm` is not yet supported as a KCC Kind, we implemented it as an external-only reference `CloudNumberRegistryRealmRef` with an initial identity structure to adhere to reference naming guidelines. `ParentRange` was implemented as a reference to `CloudNumberRegistryCustomRange` since the latter is fully supported.
- **Solution**: Defined `IPV4CIDRRange` and `IPV6CIDRRange` with uppercase capitalization in the manual `cloudnumberregistrycustomrange_types.go` file. Added `CloudNumberRegistryRealmRef` and `CloudNumberRegistryCustomRangeRef` reference files and their respective identity implementations to enable proper reference handling.
- **Impact**: Ensures that when controller and mapper reconciliation logic is implemented, the schema, identity templates, and field mapping are fully aligned and correct.
