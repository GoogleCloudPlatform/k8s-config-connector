# BigQueryDatasetAccess MockGCP Alignment Journal

- **Date:** October 29, 2026
- **Resource Kind:** `BigQueryDatasetAccess`
- **GCP Service:** `bigquery.googleapis.com` (`google.cloud.bigquery.v2.Datasets`)

## Overview

In the GCP BigQuery API, dataset access entries do not have their own standalone CRUD endpoint. Instead, dataset access is managed as an array of access control entries within the parent `Dataset` resource at `projects/{project}/datasets/{dataset_id}`. In Config Connector, `BigQueryDatasetAccess` is managed by the Terraform controller (`google_bigquery_dataset_access`), which reconciles by issuing `GET` and `PATCH` requests against the parent `Dataset` endpoint to append or remove access entries.

## Findings & Resolution

1. **Service Mapping & `idTemplate` Resolution**:
   - `BigQueryDatasetAccess` was previously missing from `config/servicemappings/bigquery.yaml`, causing KCC to fall back to the autogenerated mapping in `scripts/resource-autogen/generated/servicemappings/bigquery.yaml`.
   - The autogenerated mapping concatenated all 11 mutually exclusive access fields into `idTemplate` (`projects/{{project}}/datasets/{{dataset_id}}/{{role}}/{{user_by_email}}/{{group_by_email}}/{{domain}}/{{special_group}}/{{iam_member}}/{{view}}/{{dataset}}/{{routine}}`) as required fields, and set `metadataMapping: name: routine`.
   - This caused `pkg/krmtotf/templating.go` to fail with `Update call failed: error fetching live state: error getting ID for resource: unable to resolve missing value: dataset`.
   - Configured `google_bigquery_dataset_access` in `config/servicemappings/bigquery.yaml` with canonical `idTemplate: "projects/{{project}}/datasets/{{dataset_id}}"`.

2. **`skipImport: true` Requirement**:
   - The upstream Terraform resource `google_bigquery_dataset_access` does not implement an importer schema.
   - Without `skipImport: true`, KCC attempted to import the live resource, resulting in: `error importing resource: resource google_bigquery_dataset_access doesn't support import`.
   - Setting `skipImport: true` in `config/servicemappings/bigquery.yaml` resolved this issue.

3. **BigQuery Dataset ID Naming Constraints**:
   - BigQuery dataset IDs must be alphanumeric plus underscores (hyphens are strictly disallowed). The test fixture was structured to use `bigquerydataset${uniqueId}` rather than hyphenated names.

4. **MockGCP Compatibility & Re-reconciliation**:
   - `mockgcp/mockbigquery` already implemented `GetDataset` and `PatchDataset` with dataset access handling and sorting in `mockgcp/mockbigquery/datasets.go`.
   - Removed `BigQueryDatasetAccess` from the exclusion list in `tests/e2e/ratcheting.go`. Re-reconciliation succeeded cleanly because read requests matched existing state without detecting diffs.
   - Mock HTTP logs and golden object snapshots aligned with real GCP, passing `TestGoldenLogAlignment` and `hack/compare-mock`.
