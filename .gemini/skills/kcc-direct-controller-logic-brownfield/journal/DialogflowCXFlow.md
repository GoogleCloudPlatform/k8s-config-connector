# DialogflowCXFlow Migration Journal

## Overview
Migrated `DialogflowCXFlow` from the legacy Terraform-based reconciler to the `direct` reconciler architecture.

## Key Observations and Decisions
1. **API Client & Endpoints:**
   - Uses `cloud.google.com/go/dialogflow/cx/apiv3` (`FlowsClient` with REST option).
   - Endpoints are regional/global formatted as `{location}-dialogflow.googleapis.com` (e.g. `global-dialogflow.googleapis.com`).

2. **Service-Generated Resource IDs:**
   - Flow IDs are UUIDs generated by the GCP service upon creation.
   - Guarded `Find()` with `!a.id.HasIdentitySpecified()` returning `(false, nil)`.
   - On `Create()`, `Flow.Name` is omitted from the request payload to allow server-side ID assignment, and `a.id.Flow` is updated from the response.

3. **Diff Comparison and Server Defaults:**
   - GCP assigns default `eventHandlers` (for `sys.no-match-default` and `sys.no-input-default`) and default `nluSettings` (model type advanced, threshold 0.3) if unspecified.
   - Utilized `common.CompareGreenfieldSpec` to merge server-returned defaults into desired state, avoiding spurious updates during re-reconciliation while properly generating `UpdateMask` paths for changed fields (e.g., `description`, `nlu_settings`).

4. **Brownfield Dual-Testing Alignment:**
   - Updated `pkg/controller/resourceconfig/static_config.go` to add `k8s.ReconcilerTypeDirect` to `SupportedControllers` for `DialogflowCXFlow` while keeping `DefaultController` as `k8s.ReconcilerTypeTerraform`.
   - Ran `hack/compare-mock` on `dialogflowcxflow-minimal` and `dialogflowcxflow-maximal` fixtures to generate dual-testing golden artifacts (`_final_object_old_controller.golden.yaml`, `_http_old_controller_mock.log`, `_http_mock.diff`, `_final_object.diff`).
   - Verified 0-write steady-state re-reconciliation and passed all fixtures in `dev/ci/presubmits/tests-e2e-fixtures-suite dialogflowcx`.
