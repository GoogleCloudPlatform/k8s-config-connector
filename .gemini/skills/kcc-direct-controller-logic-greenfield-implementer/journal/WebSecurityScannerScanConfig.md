# WebSecurityScannerScanConfig Controller Logic Journal

## Observations & Patterns

### 1. Sensitive Password Fields & Custom Mappers
- `ScanConfig` contains nested authentication structs (`ScanConfig_Authentication_CustomAccount` and `ScanConfig_Authentication_GoogleAccount`) with password fields.
- To prevent raw password string exposure in KRM and adhere to KCC security requirements, passwords use `*refsv1beta1secret.Legacy`.
- To avoid type mismatch errors in generated mappers (`direct.LazyPtr(in.GetPassword())` returning `*string` instead of `*secret.Legacy`), `--skip-proto CustomAccount --skip-proto GoogleAccount` is passed to `generate-mapper`.
- Custom mappers are implemented in `websecurityscannerscanconfig_mapper.go`, mapping `*refsv1beta1secret.Legacy` to the protobuf string field.
- In `AdapterForObject`, `obj.Spec.Authentication.*.Password.NormalizeSecret(...)` is invoked when authentication accounts are provided, and `common.NormalizeGreenfieldReferences` is called.

### 2. URL Verification & Authentication Validation
- GCP Web Security Scanner requires `startingURLs` to be owned by the GCP project (e.g. `https://${projectId}.appspot.com` or Compute addresses in the project).
- If custom or Google account authentication is configured, GCP's `CreateScanConfig` actively attempts to authenticate against the target URL, returning `FAILED_TO_AUTHENTICATE_TO_TARGET` if the login endpoint cannot authenticate. E2E test fixtures test unauthenticated configurations on App Engine default domain.

### 3. Server-Generated Identity
- `ScanConfig` IDs are server-generated by GCP (e.g. numeric ID format `projects/<project>/scanConfigs/<id>`).
- On `Create()`, `a.id.FromExternal(created.Name)` parses the server-generated identifier, and `status.ExternalRef` is populated with `a.id.String()`. In `Export()`, `a.id.ID()` provides the resource ID name.
